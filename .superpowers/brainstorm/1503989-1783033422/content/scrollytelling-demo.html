protótipo — role a página

Isso é um mockup funcional pra testar o MECANISMO, não o visual final. Repare: a barra fininha aparece embaixo do menu só na zona do pipeline, e uma trilha vertical acompanha o progresso ligando os pontos de cada etapa.

new → investigate → resolve → compare → qa local → pr → qa env → merge
01 · abrir finding

/audit-new

Você descreve um comportamento suspeito. O PDD abre a finding 007, calcula uma confidence inicial e já marca no coverage map.

● ● ● audit-new
$ /audit-new "total do checkout diverge da legada"
→ finding 007 criada
→ confidence: tier-0 (textual)
→ coverage: checkout:total → finding-open
02 · causa raiz

/audit-investigate

Investigação read-only do sistema de referência (legado). Nada é alterado — só entendido.

● ● ● audit-investigate 007
$ /audit-investigate 007
→ lendo legacy/checkout/totals.rb…
→ causa: arredondamento aplicado 2x
✓ investigation.md salvo
03 · corrigir

/audit-resolve

Fix + teste de caracterização obrigatório. Cria a branch audit/007. Não commita sozinho.

● ● ● audit-resolve 007
$ /audit-resolve 007
✓ branch audit/007 criada
✓ tests/audit/007_checkout.test.ts
→ aguardando commit humano
04 · prova objetiva

/audit-compare

Golden-master harness: roda a mesma operação nos dois sistemas e gera um diff dado-a-dado. Evidência tier-2.

● ● ● audit-compare 007
− legacy: total = 129.90
+ new: total = 129.90
→ tier-2 · diff automático ✓
05 · gate humano #1

/audit-qa local

QA em localhost, antes do PR. Essa aprovação é pré-requisito bloqueante pra abrir o PR.

● ● ● audit-qa 007 local
☑ checkout renderiza total correto
☑ sem regressão visual
✓ qa-local: approved
06 · dossiê

/audit-pr

Monta o PR como dossiê de evidências. Só dá push e abre o PR depois de um "sim" humano explícito na mesma sessão.

● ● ● audit-pr 007
→ dossiê pronto: sintoma → causa → fix → diff → qa
? confirma push + gh pr create? (y/n)
✓ humano: y
07 · gate humano #2

/audit-qa staging

QA no ambiente já deployado, depois do PR. Grava qa-<env> por ambiente.

● ● ● audit-qa 007 staging
✓ qa-staging: approved
→ coverage: checkout:total → tier-3
08 · 100% humano

merge

A IA nunca autora commits. O merge é feito só por um humano — e é aí que a coverage vira "verified" de verdade.

● ● ● coverage.md
checkout: total → verified · tier-3 · #007
→ parity coverage: 63% → 68%
— fim do protótipo —
